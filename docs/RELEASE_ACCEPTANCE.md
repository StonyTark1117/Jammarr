# Release acceptance

The automated root gate is:

```bash
./gradlew releaseMatrixGate --no-daemon --max-workers=1
```

GitHub Actions runs the same release contract as 78 independent artifact jobs
with fail-fast disabled. Fabric artifact jobs also cover their matching Quilt,
Quilt with Mod Menu, and minimum-Fabric-Loader runtimes. The final `1.0 release
gate` job downloads all successful release artifacts, rebuilds the manifest and checksums,
and runs the centralized artifact inspector before publishing the candidate
bundle.

It must produce 75 JARs and three `.litemod` files plus schema-2 `manifest.json` and `SHA256SUMS` under `build/releases/`, then exercise 99 dedicated-server runtimes. These counts are derived from `gradle/targets.json` and must change with the manifest rather than being maintained independently. Run `sha256sum -c SHA256SUMS` from that directory before publication.

The release gate observes each real client's decoded output through an isolated audio sink; PLAYING state or an allocated OpenAL source alone is not accepted. Its deterministic carrier includes pseudo-random marker identities every 250 ms, and the retained JSON reports onset, marker displacement, marker-sequence mismatches, simultaneous-marker overlap, silence gaps, and inter-client skew. The oracle first proves that deliberately injected early, late, replayed, reordered, and overlapping PCM fail those checks. It also starts every modern Fabric artifact under Loader 0.19.2 as well as the pinned 0.19.3, and repeats all five Quilt client/audio scenarios with the pinned Mod Menu installed. For each audible two-client run, exercise late join, reconnect, pause/resume/skip/clear/reorder, local mute and volume, station generation, Sonic Adventure, cache-backed Plex outage playback, sound reload, underrun recovery, drift correction, and the final retry state. Confirm sound through both clients' actual output; connection state, packet receipt, decoder progress, and an allocated OpenAL source are insufficient.

Every clean two-client run must capture at least ten seconds with no post-start silence gap over 60 ms, marker displacement over 40 ms, marker-sequence mismatch count over two, simultaneous-marker overlap over 20 ms, onset over 300 ms (one 250 ms marker period plus the analysis window), or inter-client skew over 150 ms. Run `scripts/run-audio-impairment-matrix.sh` for the representative 1.7.10 Forge plus 1.20.1 and 26.2 Fabric, Quilt, Forge, and NeoForge targets. Retain all six profiles: direct, fixed 150 ms latency, 20–250 ms jitter, one two-second stall, repeated 250 ms client stalls, and six seconds below the configured stream bitrate.

Forge 1.7.10 additionally runs `scripts/run-forge1710-regression-gate.sh`. Its core phase uses the final reobfuscated JAR for persistence, a 30-minute fixture, twenty cold clients, two sound reloads per client, lifecycle transitions, pending-browse disconnect cleanup, the LiteLoader companion, and optional-client negotiation. Its impairment phase repeats sustained two-client output under all six network profiles. Dedicated-server gates hold one repository-wide runtime lock because different evidence directories still share the production game directory and ports. If the server or either client disconnects during a deterministic capture, the gate reports an infrastructure interruption and refuses to misclassify the recorder's trailing silence as an audio-timing failure.

The live Plex family smoke is the Java 8 shared-core test used by every target. It validates live library discovery and search, selected-library isolation, all station modes, 30 continuous autoplay transitions without a recent-track repeat, Sonic Adventure, and a constant-bitrate stereo transcode. On the deployment Plex, leave `JAMMARR_PLEX_LIBRARY` blank to verify preference for `Music`; optionally provide `JAMMARR_PRIVATE_PLEX_SENTINEL` for a selected-library search that must return no result from the separate ASMR library. Credentials and sentinel values remain process-environment-only and retained logs must not contain them, the server address, or the token.

On 2026-08-30 the shared-core live smoke passed with the deployment Plex, blank library selection, and a real ASMR-library item supplied as the private exclusion sentinel. The run selected `Music`, kept that ASMR item out of selected-library search, covered browse/search/stations/Sonic Adventure/transcode, and completed 30 autoplay transitions without a recent-history repeat. Treat this as shared-core evidence, not as a substitute for final-JAR family runtime, two-client audible, or DiscPanel acceptance.

`verifyDedicatedServers` launches a deterministic loopback Plex service and every runtime, including every modern Fabric artifact under pinned Fabric and Quilt loaders. Before its valid startup, each runtime must reject an intentionally invalid canonical config, fail closed, keep the invalid file unchanged, omit its credential value from diagnostics, and release the game port. Each valid server must then authenticate with the environment token and complete library discovery, server-identity, and sonic-analysis requests. Set `JAMMARR_DELAYED_HELLO_GATE=true JAMMARR_GATE_HELLO_TIMEOUT_MS=60000` to make every real client hold its application hello for 12 seconds, receive the server hello, and remain connected; `JAMMARR_DELAYED_HELLO_MS` may select another acceptance-only delay below 60 seconds. Every runtime launches its matching real client with an intentionally incompatible protocol and requires either the exact protocol-6 reason received by that client or an exact server marker paired with the loader's generic client disconnect. Missing-client probes keep an unmodified client connected for at least ten seconds and prove that it never gains Jammarr capability. Matching clients with an intentionally suppressed application hello traverse the loader handshake but are excluded from Jammarr functionality after the explicit hello timeout. Shared tests additionally reproduce the 1.0.1 Uranium re-entrant logout failure and enforce acceptance at 59 seconds with expiry at 60 seconds.

Client-only companion artifacts are paired with their manifest-declared server loader rather than counted as standalone dedicated runtimes. Set `JAMMARR_CLIENT_COMPANION_GATE=true` to launch each production-reobfuscated companion against that paired server and require protocol negotiation, its player and configuration screens, observable fake-Plex audio reaching PLAYING, a further ten seconds of connection health, and clean server teardown.

Every automated client GUI launches on a fresh private Xvfb display with an isolated game directory and the active Wayland display unset. Release validation must not open windows on, inject input into, or otherwise interact with the active user's desktop session.

The harness then launches another real client as a non-operator. Modern clients must receive a command tree containing public `status` but not operator-only `diagnostics`; after promotion, the server must resend a tree containing both. The promoted client executes `/jammarr diagnostics` and must visibly receive a `Plex=` health summary. The legacy client executes public status and operator diagnostics directly, must receive the denial before promotion, and must receive the diagnostics summary afterward. Both the real player response and authenticated administration response are rejected if they contain the token, an HTTP URL, loopback address, localhost, or a Plex token header. Forge 1.7.10 overrides vanilla's all-or-nothing non-op command gate so its public root/status behavior matches modern targets while retaining Jammarr's subcommand checks.

Finally, the harness requests shutdown over authenticated loopback RCON (or the working legacy console), and fails on missing Plex requests, missing client evidence, missing save/shutdown markers, a lingering process group, or a listening game/RCON port. It uses an isolated gate world, removes the temporary operator, and restores each pre-existing `server.properties` and canonical server config byte-for-byte after both runs. Console, client, connection-probe, command, and fake-Plex request evidence is written under `build/dedicated-server-gate/`. The centralized artifact inspector validates every final artifact's exact metadata and bytecode targets, including Forge 1.6.4's guarded ASM-4-compatible major-51 headers, the shared coordinator contracts, loader Controls registration and configured-key consumption, bundled core/JLayer/Jump3r libraries, mappings-appropriate Mixins (and their intentional absence on pre-Mixin Forge), icon alpha, translations, licenses, notices, checksums, canonical filenames, and absence of an environment token or RFC1918 deployment address.

Keep the generated `*.wrong-protocol-client.server.txt` and `*.command-client.evidence.txt` files with release evidence. These prove the authoritative rejection, non-op/operator visibility transition, rendered player/config screens, real player response, and diagnostic redaction for the exact built target; readiness alone is not a substitute.

DiscPanel instances are reconciled from the same runtime manifest with `scripts/reconcile-discopanel-test-servers.py`. Run it without mutation flags first. `--apply-native` may then create only missing Forge, Fabric, Quilt, and NeoForge instances, one at a time, with pinned Java images, no immediate start, no autostart, and no Jammarr upload. `--apply-custom` is restricted to the manifest-declared Fabric-derived legacy profiles: Babric and Legacy Fabric use versioned launcher URLs pinned by SHA-256, while Ornithe receives an inspected generation-2 bootstrap archive at the server root rather than a mod upload. `--verify-custom-launchers` performs a read-only download-and-digest check. The reconciler refuses drift in Minecraft version, loader, Java image, memory, stopped state, custom environment, or required Ornithe bootstrap.

The 2026-08-30 reconciliation reused 21 instances and created 78, producing all 99 exact runtime profiles. The pre-deployment audit found all 99 stopped, zero error or running states, 99 unique game ports, exact environments for all five custom profiles, matching remote/local launcher digests for both Ornithe bootstraps, and zero mod records on every newly created instance. All three URL-based custom launchers were independently re-downloaded and matched their pinned SHA-256 values.

Release artifacts are staged with `scripts/deploy-discopanel-release.py`, which is read-only by default. Before proposing a change it verifies the complete 78-artifact release manifest and `SHA256SUMS`, hashes every local file, excludes the three client-only LiteLoader companions, and maps the 75 server artifacts to all 99 runtime profiles. It rejects any missing, running, autostarted, drifted, duplicate-active, digest-mismatched, or partially deployed profile. Applying requires `--apply --confirm-version 1.1.0`; after import it hashes the remote `mods/` file, then disables rather than deletes the previous active Jammarr record and confirms the server remained stopped.

The 2026-08-31 deployment staged all 99 exact 1.1.0 runtime artifacts. A complete read-only rerun reported 99 already verified and zero remaining deployments; a separate audit found 99 active 1.1.0 records, zero active older Jammarr records, and 21 stable 1.0.2 files retained disabled as rollbacks. All 99 servers were stopped and autostart-off immediately after staging, and the deployment workflow never issued a start. Forge 1.7.10 was later started externally for user testing, so description normalization deliberately skipped it while active and changed only the other 98 stopped profiles. Staging and byte parity do not substitute for runtime, real-Plex, mixed-client, audible, or final user acceptance.

The deployer also derives and verifies exact native loader environment pins from the release manifest. `scripts/configure-discopanel-live-plex.py` is separately dry-run-by-default and requires explicit runtime selections plus `--apply --confirm-library Music`. It copies no secret into the workspace or canonical config: the source token is moved to `JAMMARR_PLEX_TOKEN`, the library is blanked to exercise `Music` fallback, and `--missing-only` preserves existing differing configs. On 2026-08-31 this prepared 78 stopped profiles and skipped 21 existing configs; a verification rerun reported `already=78`, `configure_required=0`, `conflicts=0`, and `skipped_existing=21`. The exact 1.12.2 Forge candidate subsequently reached Minecraft readiness and live Plex connection, then stopped cleanly. The first attempt failed during an upstream Forge-installer manifest download and is not counted as a mod failure. No client-side or audible claim follows from this server canary.
